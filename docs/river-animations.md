## Trajectory gates (attempt 5)

A gate that only asks "did something move" passes when a row jumps, turns the wrong way or is not drawn. shot.sh now checks the path:

- `AMPLIFY_RIVER_TRACE=1` (settle and fx runs) makes River.qml log each drawn position as it changes: `amplify: river trace vessel|vy|gate|tether|rings <key> <value>` (hull centre x, hull centre y, gate x, tether hull end x2, REJECT rings rotation), starting with the value the delegate was made with. `plugin/river/test/trace.mjs` reads them.
- `slide`: start → end with at least 3 samples strictly between (1 px clear), first moving toward the end, no step over half the distance. Rows 5, 2.
- `ease` (attempt 6): as `slide` without the direction rule, on the hull centre y of the vessels that change row. Row 11. (y follows both the river curve and the row offset and is logged once for each, so it can tick a pixel the other way first.)
- `follow`: every tether end slides with its vessel and stays within 1 px of the hull's own samples. Row 3.
- `turn`: the REJECT rings go one way from 0 to -140°, at least 10 samples between, no step over 35°. Row 8.
- Still runs check the drawn geometry: tethers.mjs checks the lit ShapePath ends at the de Casteljau split of the drawn tether at the fixture's lease (row 4); `motion.mjs gold` counts the PASS ring's gold on its radius (row 7); the REJECT rings log their rotation (-70° at p = 0.5).
- `motion.mjs flow`: three flowing frames 0.2 s apart; the change between the first two reappears in the next pair shifted downstream (+17 px at 90 px/s; correlation 0.94, -0.16 the other way). Row 1.

## Audit for the attempt-2 bug class (wrong pivot, never ends, moves without a record)

- **Wrong pivot.** Row 6 was the bug (E1): fixed with `transformOrigin: Item.TopLeft`. Row 8 rotates a zero-size Item, so it already turned about its landing point. The design canvas scales about `Item.TopLeft` (L142). No other rotation or scale exists.
- **Never ends.** Two more cases besides E2, both fixed:
  - Two effects finishing in the same frame: `Qt.callLater(river.dropFx, uid)` merges repeated calls to the same function, so only the last effect was dropped and the other stayed in the model forever (seen in the PASS + REJECT busy fixture: only `fx done pass` was logged). Each effect now passes its own closure.
  - Still mode never ran the effect animation, so effects were never dropped and piled up step after step while the replay clock ran. They are now dropped at each scene step (shot.sh `replay`).
  - The swirl kept animating while the river was hidden. It now also stops on `!visible`, like the water clock.
- **Never moves (attempt 4).** Row 2's `Behavior` never ran: the gate `Repeater` took `lay.gates`, a new JS array each scene, so it rebuilt its delegates and the gates jumped while the vessels sailed. Gates now sync into a `ListModel` keyed by lane, like vessels and tethers (an undamped gate spring now fails `settle` and `fx`).
- **Moves without a record.** None found. Every row above is bound to a scene value from a record. The idle gate shows that a scene with no recent updates, no blocked task and no verdict produces identical frames.
